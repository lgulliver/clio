# Clio architecture

## Current boundary

The browser application is a client-side React SPA; a separate local Node 24 API owns PostgreSQL persistence. Vite builds it; TanStack Router owns file-based navigation and TanStack Query owns scoped remote/server-state caching. Tailwind supplies styling. Biome owns linting, import organisation and formatting. Vitest and Testing Library check browser behaviour in jsdom.

The workspace has these boundaries:

- apps/web: presentation and user interaction. Routes are thin composition points. Identity/session and workspace flows live in src/features; shared UI stays in src/components, foundational client utilities in src/lib.
- apps/api: server-only Fastify JSON HTTP transport, explicit SQL migrations and node-postgres repositories for workspaces and scoped services. Native Node TypeScript runs the API; there is no separate server build pipeline. Better Auth owns GitHub login and PostgreSQL sessions; Clio owns transactional workspace membership, service authorization and member invitations. The auth transport exposes only login, callback and logout; /api/me returns safe identity.
- packages/oems: platform-neutral integration with the pinned standard. Implements pinned local schema checks, separate semantic validation, immutable validated snapshots and all five per-service calculations. Bigint microsecond timestamps preserve ordering; nulls and provisional quality retain missing evidence. Runtime supports native Node 24 and browser bundling; normative changes still belong upstream.
- packages/adapters: server-only GitHub App token/full-backfill helpers, supplied Argo CD operation normalization and pure deployment evidence reconciliation through the pinned OEMS validator. Configurable mock demo and fictional fixtures establish behavior; mock-only setting APIs/UI consume this foundation; a separate strict native notification parser maps authenticated Application fields to the existing normalized boundary. Separate mock API jobs persist fictional snapshots/results. Live GitHub helpers verify App/installation/account and narrowly scoped repository access, bound network acquisition, and preserve normalized deployment/status history.
- packages/typescript-config: shared strict compiler defaults; no runtime code.

Internal TypeScript packages expose source to the workspace bundler and have no separate publishing/build pipeline. All packages are private. Introduce distributable builds only when there is a real external consumer.

## Evidence flow

Provider collection on a trusted server -> reconciled evidence snapshot -> pinned OEMS validation/calculation -> result API -> TanStack Query -> UI.

The [GitHub mapping verification](providers/github-oems-verification.md) traces controlled HTTP responses through stored history and the actual capture into all five OEMS calculations. The implemented [Argo enrichment contract](superpowers/specs/2026-10-10-argo-enrichment-design.md) keeps independent consumer-exposure and artifact/source assertions separate from immutable native operations. Capability-scoped producer grants, shared bounded storage, rotation fences and exact operation/artifact joins are verified with fictional producers. See the [operator setup guide](providers/argo-enrichment.md).

The [durable Argo history contract](superpowers/specs/2026-10-10-durable-argo-history-design.md) adds source-side journaling and independently authorized historical import. Strict validated envelopes, contiguous checkpoints, immutable authority lineage and seals preserve original observation provenance while current receiver time controls snapshot availability. Unsupported native payloads become retained archive gaps without blocking later valid entries. Archive pacing reserves live ingress headroom; all storage remains source-lifetime bounded. The [operator guide](providers/argo-history.md) explains capture and replay bounds. An opt-in [scoped Kubernetes list/watch collector](providers/argo-continuous-capture.md) binds one exact Application and private operator context to a fixed durable capture checkpoint. Independent capture/sender ownership and short journal transactions let acquisition continue during receiver outage. Restart, watch loss and relists preserve conservative missing periods; source history and all OEMS coverage remain incomplete. New Argo snapshots save a [coverage evidence assessment](providers/argo-coverage.md) at the same cutoff; Settings/Overview display cohort-specific missing evidence counts without recomputing older results or promoting flags.

Do not skip the validation/quality boundary or send provider credentials to the browser. The result must retain service, window, cutoff, version and provisional-quality information. Query clients must be scoped to an application/workspace/request rather than a cross-user global cache. Browser identity checks hide private workspace UI, cancel queries and clear caches on mount/focus identity changes and visibility transitions. Identity revisions and workspace scope guard late query and mutation results. Settings workspace selection and invitation tokens remain in memory, never browser storage. Overview URLs carry allowlisted workspace/hierarchy IDs and comparison filters for shareable views; every restored scope still requires current workspace authorization, and copied links exclude credentials and result payloads.

PostgreSQL workspace/service persistence and transactional, checksummed migrations are implemented for local development. ADR 0004 selects Fastify and node-postgres; Docker Compose binds PostgreSQL 17 to loopback. API startup does not migrate. Readiness requires database connectivity, current migration history and expected table columns. Internal repositories require workspace IDs; callers must establish membership before using them. Better Auth with GitHub login, PostgreSQL-backed sessions, and workspace membership is selected in ADR 0003; the server integration is implemented with cookie caching and implicit account linking disabled. ADR 0005 records owner/member policy and hashed invitations. Login OAuth tokens are discarded after identity retrieval. ADR 0007 selects a separate local PostgreSQL-backed mock worker with leased claims and bounded retries. Deployment hosting and live collection scheduling remain undecided.

## Frontend operational requirements

The [Engineering drill-down](engineering-drilldown.md) organizes a workspace into teams, products and services. Products have one owning team; services have one optional product assignment. Current ownership is separate from immutable collection/measurement context and workspace authorization. Owners configure and rename the hierarchy, move products, delete empty teams and delete products while preserving their services as unassigned; members read it. Lifecycle changes use the existing authorized workspace transaction and preserve immutable results. Migration 0014 enforces workspace-bound ownership through composite foreign keys. Group views compare safe saved service results from one selected source, loading ten services per page; they do not calculate group-level OEMS metrics or average service medians. Service navigation retains existing evidence and trend boundaries.

Shared reporting-window selection aligns comparison rows to exact UTC bounds from each visible service's bounded saved history. It persists across organization scopes and service pages, while a source change resets it. Group charts display individual service series, filtered by selected provider/revision/OEMS context, with an end cutoff only for an explicitly selected reporting window; points use reporting-window start times, and segments require that service’s own adjacent, non-overlapping windows. Missing intervals, null values and legacy captures remain gaps. Dynamic query pages own distinct identity-scoped caches and abort abandoned reads. Refresh only reads saved history. Page-scoped coverage/freshness summaries preserve per-metric OEMS status, missing/read-failure distinctions and separate collection-basis, result-evidence and completion clocks. User-selected evidence-age thresholds do not assert an SLA or complete coverage. No group metric aggregation is performed. Optional exact current/previous window comparisons reuse those reads and gate signed per-service deltas on matching source/revisions, equal-length chronological windows and complete numeric metrics. Both result contexts and quality remain visible. A collapsed service comparison preserves the same filters alongside native evidence histories.

Workspace owners can use an inline five-step [source setup wizard](providers/source-setup-wizard.md) to select a service/source, configure the existing provider scope, collect a saved reporting window and review independent evidence. Provider controls remain mounted across presentation steps to preserve drafts and collection confirmation state. Progress depends on scoped saved configuration and successful results for the current revision, never enqueue success or empty history. The wizard reuses provider authorization, cache and stale-response fences; source credentials and independent reports remain server-side. Finishing a setup review does not promote coverage or metric quality.

The app is a SPA, so production hosting must serve index.html for navigable application paths such as /settings, while serving assets normally. Client error/unknown-route states are present. No external fonts, telemetry or credentials are loaded by the shell.

VITE_ values are public configuration. Keep browser/server TypeScript environments separate. The generated route tree is committed and ignored by the formatter; CI rebuilds and checks it remains in sync.

GitHub production requests and Argo ingress share [PostgreSQL-backed rate controls](providers/rate-limits.md). Installation acquisition leases, App-wide request pacing and monotonic cooldowns cover GitHub connection verification and collection; Argo source buckets survive replicas and restart. Incremental collection and webhook updates remain pending.

## Developer experience: SPACE pulses

SPACE uses the separate application contract `clio.space.pulse.v1` in `apps/api/src/features/space` and `apps/web/src/features/space`. Its original eight-item pilot instrument reports self-perceived satisfaction, performance, activity, collaboration and flow. It is not a validated psychometric scale, measured operational activity or an OEMS delivery result. Question means stay on their original 1–5 scales; dimensions and teams are never combined into a productivity score.

Migration 0015 adds workspace preferences, one optional primary team per current member, own assignment history, pulse metadata, private frozen rosters, submission receipts and temporary unlinked answer rows. Current assignments have workspace-bound membership/team foreign keys; they do not grant permissions or change product ownership. Opening freezes the cohort, copied team identity/name, instrument, reference period and minimum (3–1000, default 3). Existing authorized workspace transactions serialize membership changes, assignment changes, lifecycle and submissions. Overlapping reference periods are rejected across open/closed pulses sharing any participant, including different teams. Archived team identity survives deletion; draft/open pulses block team deletion.

Every read rechecks session and membership, every owner write rechecks role and trusted Origin, and every response admits only the current eligible actor. Separate unique receipts prevent duplicate answers without a respondent-to-answer join or matching timestamps. Close/cancel deletes all raw answers transactionally. Closed question aggregates suppress every count below the frozen minimum, including zero; owners cannot bypass question suppression. Open aggregates remain hidden, participation totals follow current-role visibility, and cancellation retains no totals. This is confidential reporting within the application, not guaranteed anonymity against administrators or collusion. Backup/account deletion policy and hosted retention remain separate decisions.

Developer experience provides workspace/team scopes, an owner setup wizard, nullable member responses with confirmation, bounded archives and question-level trends. Trends use reference-period starts, preserve original team names and cohort context, split instruments/period lengths, and join only adjacent published periods. Suppressed, open, cancelled and missing intervals remain gaps. Browser reads/writes retain existing identity revision, cancellation and access-loss fences. See the [pulse guide](space-getting-started.md) and [HTTP contract](space-api.md).

## Developer experience: GitHub operational signals

The separate application contract `clio.space.github.v1` keeps repository observations outside pinned OEMS delivery semantics and confidential pulse answers. Server-only adapters verify a PR-only App and selected repository, collect bounded normalized PR/review facts, and discard transient person identities. A distinct App ID and capability-bound operator grants separate this from GitHub deployment collection. API and worker load configuration at startup; changing files requires restarting both.

Migration 0016 stores revisioned workspace/team repository mappings, durable jobs, private checkpoints/evidence and immutable safe results. Owner writes use current session/membership checks and trusted Origin; source verification occurs outside transactions with postflight authorization/grant/revision fences. Worker machine authorization checks current connection, grant and lease without impersonating an interactive user. Disconnect detaches live ownership and fences acquisition while copied historical team/source context remains readable. Connected mappings or active jobs block team deletion.

Acquisition reuses durable App/installation quotas, one-request-per-second App pacing and provider cooldowns. Verification and resumed author lookup share each slice's deadline/request counter. Claims last 120 seconds, slices allow 60 active seconds/40 requests, and jobs allow 30 minutes cumulative acquisition, 24-hour lifetime and three retryable failures. Contention, cooldown and cooperative continuation do not consume attempts. Atomic completion persists accepted normalized evidence and safe calculated output under current lease/grant/revision fences.

Counts include observed PR creation/merge events and eligible human review submissions. First-review timing uses human PRs opened in the window with completed review traversal and a qualifying review before its end. PR review time uses valid human PRs merged in the window, independently of review traversal. Both conditional medians require three samples and include draft, author and queue time. Empty observations remain null; every numeric signal remains provisional. Traversal completion never establishes historical completeness.

Developer experience adds a four-stage source wizard, independent run/success history, five metric cards and qualified timestamp-positioned trend points. Series preserve repository, mapping revision, copied team, calculation version and window length; incomplete historical populations are not joined by chart lines. Repository rows are not pooled into team/workspace scores or attributed to services/products. Read the [real-source setup guide](providers/connect-space-github.md) and [HTTP contract](space-github-api.md).

## Independent measurements

The implemented [measurement evidence contract](providers/measurement-evidence.md) adds service-scoped population, change/history, classification and recovery reports to an exact successful GitHub or Argo collection basis. The private basis binds native source identity, connection revision, OEMS revision, native snapshot and normalized evidence digests, and retained gap manifest. Producers cannot create native deployments or alter qualification. Machine ingress uses independent capability-scoped producer grants, not browser sessions or login OAuth credentials; follow the [operator guide](providers/connect-measurement-evidence.md).

PostgreSQL retains immutable reports, source-lifetime fact/byte budgets and durable measurement jobs. Authenticated machine reads and submissions share a persisted request budget; rejected submissions do not erase pacing. Source and producer eligibility is checked at admission, enqueue, claim and completion. Jobs pin selected report IDs and digests, preventing later reports from changing queued inputs. A separate `pnpm worker:measurement` calculates through the pure adapter reconciliation and pinned OEMS boundary outside the storage transaction, then atomically saves the private snapshot and safe all-five result. Leases expire after 120 seconds; attempts are bounded to three. Startup requires explicit current migrations, including `0011_measurement_evidence.sql`.

Owners select a successful native basis and received reports in Settings. Selecting no reports is valid and yields an honest partial measurement; private measurement grants are optional for this case, while current native source access remains required. Complete metrics require independently supported evidence, reconciled deployment paths/history/gaps, and the pinned metric-specific conditions. Coverage declarations remain independent of each other and of individual metric quality. Original native collection coverage and completed results never change.

Saved measurements expose the original basis cutoff and a strictly later database measurement cutoff, reporting window, pinned revision, safe blockers, coverage and exact five metric objects. Private payloads, references, tokens and fingerprints remain server-side. Owners and members browse bounded immutable measurement history in Overview; completed history remains readable after producer revocation while workspace authorization still applies. The [local MVP acceptance scope](agents/feature-completion.md) records final verification separately from implementation.

## Current limitations

The UI displays unconnected, empty, pending and failed states without fabricating evidence. GitHub login/logout, workspace/service workflows, manual invitations and owner access controls are connected. Member and invitation lists have independent bounded cursor pages; cancellation and revocation clear affected in-memory invitation tokens. Owner membership remains protected, and current session/membership checks govern private reads and writes.

GitHub, Argo and fictional mock results have separate immutable histories. Recent requests and successful results are read independently, so newer failures cannot hide older successes. Bounded saved-window pages replace each other; manual refresh reads storage without triggering collection. New native results retain all five pinned metric objects, while legacy results remain readable without recomputation. Native deployment counts are provisional; all initial native coverage remains incomplete. Historical repository/Application names are absent from these safe result contracts, so source labels identify providers only. Counts across overlapping sources must not be added.

Live GitHub collection requires a separately configured GitHub App and private scoped operator grants. GitHub workers preserve deployment/status history, bounded acquisition, resumable checkpoints, database-clock leases and revision/grant fences. Native Argo ingress and snapshot workers preserve exact Application scope and bounded receipts/gaps. Independent Argo exposure, application provenance, source journals and scoped continuous capture require separately configured producers and operator supervision. Synced/Healthy alone does not establish consumer exposure or application source lineage. Source journal replay does not prove complete coverage.

The independent measurement workflow is implemented locally; final integrated checks, opposite-engine review and browser acceptance remain pending for this delivery. Complete live measurement coverage requires actual independently exhaustive producers and verified policies, not fixture success. Deployment hosting, hosted credential onboarding/storage, automatic scheduling and incremental GitHub/webhook acquisition remain unselected or unimplemented. Local feature completion does not establish production deployment or OEMS conformance.
