# Resumable GitHub acquisition

Apply migration `0008_github_checkpoints.sql` explicitly, then restart API and GitHub worker. Existing migrations remain unchanged. No GitHub credential or provider URL is stored in checkpoint state.

Each successful collection run atomically saves accepted normalized evidence, its immutable provisional snapshot and the next unaccepted deployment/status page. The next explicitly requested run for the same connection continues that sweep. A successful partial result does not schedule another run. Existing snapshots remain unchanged as later evidence arrives.

Progress is scoped to workspace, service, connection revision, GitHub App, installation, repository and operator grant fingerprint. Connection edits or grant changes begin a fresh sweep. Credential rotation alone does not reset progress when the grant identity is unchanged. Quota cooldowns remain independent and cannot be reset by changing a connection.

The worker re-verifies provider access and numeric repository identity on every run. URLs are derived from trusted repository metadata and numeric cursor fields; incoming pagination links retain fixed-origin/path/page checks. Cursors contain one deployment page and at most 100 pending deployment IDs with their next status pages. Deployment pages are interleaved with status collection so a large deployment list cannot indefinitely postpone every status scan. Pages advance only after parsing, link validation and evidence acceptance. A failed unaccepted page remains the next page.

GitHub REST page offsets can move between acquisitions. Resumed status tails never produce completed-status-traversal evidence, even when the tail reaches its last page. A status scan that starts at page one and finishes within one acquisition can record traversal completion. Completing a sweep resets its cursor so the following run starts at page one for catch-up. This approach retains positive evidence and makes progress through large histories; it does not establish a stable source snapshot or complete OEMS coverage. Source changes during a sweep can cause duplicates or omissions until a later catch-up sweep. New source events are not necessarily seen immediately while an older sweep is being resumed.

All initial coverage flags remain false. Missing changes, incidents, recovery and rework evidence remain unsupported; checkpoints do not alter the pinned OEMS semantics or supply zeros for missing evidence. `transportComplete` is true only when acquisition starts at deployment page one without pending status scans and finishes within the same run. Finishing a resumed sweep resets its cursor but keeps `transportComplete` false. Neither case asserts complete OEMS coverage.

Network work remains bounded to 60 seconds, 100 requests/pages, 5,000 acquired records and the existing byte limits. Retained history still has its separate 5,000-row/8 MiB budget; checkpoints do not expand it. Hard acquisition cancellation, shutdown, lost leases, revoked grants, evidence conflicts or completion failures preserve the last committed cursor. Useful accepted prefixes can commit before the hard deadline. Empty pages can also commit genuine cursor progress without asserting coverage.

A deleted or inaccessible pending deployment, consistently malformed page or exhausted retention budget can prevent further progress. An incomplete acquisition with no cursor progress retries, then fails visibly after three attempts even when older evidence is retained. Clio does not silently skip the resource. To restart traversal after a deleted or inaccessible resource, save an edited connection revision after correcting access; the new revision starts at page one and preserves prior evidence and snapshots. This does not bypass the retained-history budget. Dedicated cursor recovery controls, conditional requests, webhooks, scheduling and scalable retention remain future work. Real GitHub App collection still requires operator configuration and live verification.

Controlled adapter tests cover multi-run pagination, shifted duplicate pages, fresh versus resumed traversal proof, unsafe links and strict cursor parsing. PostgreSQL tests cover worker reconstruction, retained evidence and immutable snapshots, revision/workspace isolation, empty-page progress, completion rollback and stale checkpoint writes. These tests do not prove a real installation's permissions or data availability.

Reference: [GitHub deployment endpoints and page parameters](https://docs.github.com/en/rest/deployments/deployments?apiVersion=2026-03-10).
