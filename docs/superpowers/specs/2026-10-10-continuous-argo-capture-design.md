## Intended result and alternatives

One explicit Application list/watch collector retains contemporaneous native observations before Clio delivery, continues capture during receiver outage, resumes durable progress and reports conservative acquisition interruptions. It never reconstructs overwritten operations from status.history, fabricates operation identity or treats resourceVersion as deployment identity.

A notification relay alone cannot observe notifications that Argo never emits or loses after bounded retries. Polling current state alone also misses overwritten operations. Scoped Kubernetes list/watch is selected: it sees real Application changes and exposes disconnection/expired-history boundaries. It still cannot recover all source history or attest completeness.

[Kubernetes API concepts](https://kubernetes.io/docs/reference/using-api/api-concepts/) define opaque resourceVersion cursors, finite watch history, optional bookmarks and relist after 410 Gone. [RBAC guidance](https://kubernetes.io/docs/reference/access-authn-authz/rbac/) describes name field selectors for resourceNames-scoped list/watch. No watch bookmark or clean reconnect alone establishes complete population coverage.

## Private operator configuration and transport

A separate Node24/Linux CLI, `pnpm argo:capture --config /absolute/private/capture.json`, uses an explicitly chosen absolute kubectl executable, owner-only kubeconfig outside Git, explicit context and exact full native scope. Config also binds journalDirectory, existing producerId/journalId/policyReference, and receiver baseUrl/tokenFile. All configuration and private payloads remain server-side. Initial operator-created journal must match these identities and policy; scope is immutable for the collector's checkpoint lifetime.

Use a trusted operator kubeconfig. Its context may contain operator-approved credential exec plugins; this tool does not accept kubeconfig URLs or generate credentials. Real operators grant only get/list/watch for the selected Argo Application via a namespace Role, resourceNames and `metadata.name` field selector. No global current-context mutation, Kubernetes writes, secret listing or arbitrary provider endpoint is needed by the collector. Production TLS verification remains enabled; explicitly trusted local development context may use its configured development endpoint.

Spawn kubectl without a shell, with explicit kubeconfig/context, fixed Argo v1alpha1 namespaced Application API path and name selector. A list request is bounded by 15s and one bounded JSON document; a watch requests a 30s server timeout with a 35s client ceiling. Only this selected name is watched. Never log raw stdout/stderr, kubeconfig contents, tokens or payloads. Parse unknown JSON, bound each document/event at 512KiB and stream framing buffers at 512KiB. ResourceVersion strings are opaque bounded strings, not arithmetic cursors. Errors use redacted codes. Proxy environment is rejected rather than silently routing private traffic elsewhere.

## Acquisition and durable progress

Project actual Application fields through existing applicationNotification. Bind actual UID/name/namespace/project/repository/destination to configured scope before capture. Recreation/UID drift, deletion or scope drift stops acquisition explicitly; it cannot silently become a new source. Preserve missing identity, Running, unsupported/multi-source/hydrator and missing temporal fields for existing receiver gaps. Native terminal horizon and historical capture semantics remain unchanged.

Persist original observation with current local capture clock before advancing the resourceVersion checkpoint. Bookmarks advance only cursor/contact progress, never create native evidence. Annotation/bookkeeping updates whose projected native payload is unchanged do not append again. Exact latest projected payload already durably retained can be reused after a crash before checkpoint update; A→B→A appends all three states. Changed UUID, phase, health timestamp, revision, info or initiator is not deduplicated into another operation. Digest/sequence/capture times of prior entries never change.

Maintain one fixed-size, owner-only capture-state.json with exact config/scope fingerprint, opaque cursor, last known contact and current unsealed period. Atomically flush it using a separate pending file and directory fsync; do not append unlimited attempts/logs. One independent crash-safe capture lock admits one watcher per journal. Restart checks the durable journal as authority; a checkpoint cannot advance past unretained observations. Uncertain crash/ordering state fails closed or preserves a conservative interruption, never skips retained evidence.

Clean rollover uncertainty accumulates in fixed checkpoint state, coalescing overlapping gaps. Hourly cadence seals the period. Overflow beyond 32 separate gaps conservatively unions all missing bounds, also marking intervening contacts uncertain. Restart closes a positive incremental seal; all reconnect failures coalesce until hourly cadence, including flapping after bookmarks or successful lists. Record conservative missing bounds from last trustworthy contact to reconnect/restart, including disconnect, expired cursor/relist and collector downtime. Initial current-state list observes only present state; pre-start history stays unknown. Relist after 410 cannot fill the missing interval. Interruption intervals are ordered, nonoverlapping, bounded at32; conservatively union overflow without dropping missing bounds. Clean bounded watch completion may still carry a conservative contact-to-reconnect interruption. Quiet streams/bookmarks are not proof of no missed deployments.

Unrecoverable malformed events, UID/scope drift, clock rollback, capacity exhaustion or filesystem corruption stop visibly. Never prune, reset budget or silently drop records. Retained evidence and last durable capture checkpoint survive. Abrupt outage after last seal remains visibly unsealed; restart closes it with conservative downtime evidence. Negative/zero-length seals are never fabricated.

## Concurrent delivery

Current drain holds the journal writer lock during HTTP/backoff and prevents capture. Replace that with an independent sender lock plus short journal transactions. Persist the planned attempt/cooldown under writer lock, release it before waiting/network, then reload fresh durable state before committing acknowledgement. Verify selected immutable body/index still matches. Capture and seals can append during a blocked fetch; a sender cannot overwrite newer retained counts or another acknowledgement. Two senders cannot send the same pending index concurrently. Crash after receiver commit still resends exact bytes and returns original receipt.

The collector runs a bounded one-attempt drain batch alongside acquisition, with existing durable cooldowns and maxWaitMs0. Storage locks are never held across waits/network. Transient receiver failure does not stop capture; explicit permanent delivery conflict is surfaced while retained acquisition continues until its finite capacity. On shutdown cancel watch/subprocess, stop scheduling new sends, finish bounded current storage operations and preserve unsealed uncertainty. Each process/network operation has finite timeout and retry/backoff, though an explicitly started collector runs until signal/operator stop.
